NT I/O completion ports
=======================

The IOCP extension adds a file-backed FIFO of completion packets to an ntsync
instance. File descriptor duplication gives multiple processes access to the
same port while the existing ntsync device continues to define the NT virtual
machine boundary.

An IOCP object is signaled while its queue is nonempty. Acquiring the object
through ``NTSYNC_IOC_WAIT_ANY`` or ``NTSYNC_IOC_WAIT_ALL`` does not remove a
packet. Packet removal is a distinct operation, matching the difference
between waiting on an NT completion-port handle and calling
``NtRemoveIoCompletion``.

Interface
---------

``NTSYNC_IOC_CREATE_IOCP``
  Creates an empty completion port. The concurrency value is retained for the
  future implementation of the NT active-worker limit but is not enforced yet.
  ``version`` must be ``NTSYNC_IOCP_VERSION``. The current interface version
  is 1. A new port starts at ``NTSYNC_IOCP_INITIAL_GENERATION``.

``NTSYNC_IOC_IOCP_POST``
  Appends one packet to the port. Packets are ordered by successful post
  operations. Queue allocations are memory-cgroup accounted. Application
  posts fail with ``ENOSPC`` when the port already has 65536 pending packets.
  A packet remains pending while a removal copies it to userspace.

``NTSYNC_IOC_IOCP_POST_INTERNAL``
  Appends a packet from the compatibility runtime without applying the
  application posting limit. This prevents completions generated by I/O or
  job state changes from being lost merely because application posts filled
  the queue. Allocation failure is still reported as ``ENOMEM``.

``NTSYNC_IOC_IOCP_REMOVE``
  Removes the oldest packet without blocking. It fails with ``EAGAIN`` when
  the port is empty. A failed userspace copy leaves the packet queued.

``NTSYNC_IOC_IOCP_REMOVE_BATCH``
  Removes between one and ``count`` packets. If the queue is empty, the
  operation waits for the first packet, an optional alert event, or an
  absolute timeout. Once one packet is available, the operation removes as
  many packets as are already queued, up to ``count``, without waiting for the
  remainder. ``count`` must be between one and
  ``NTSYNC_IOCP_MAX_REMOVE``.

  ``packets`` points to an array of :c:type:`ntsync_iocp_packet` entries and
  ``written`` receives the number removed. ``timeout`` and ``flags`` use the
  same absolute MONOTONIC or REALTIME clock convention as
  ``NTSYNC_IOC_WAIT_ANY``. ``U64_MAX`` waits indefinitely. ``alert`` may be
  zero or an event descriptor from the same ntsync device. When the alert
  event wins the wait, the ioctl succeeds with ``written`` set to zero. A
  queued packet takes priority when both are already signaled.

  ``generation`` identifies the current removal lifetime. A nonzero stale
  generation fails with ``ECANCELED`` without removing a packet. Zero selects
  the current generation for callers that do not need abandonment semantics.

  Blocking removers are served in LIFO order. They take priority over threads
  waiting on the IOCP object through ``NTSYNC_IOC_WAIT_ANY`` or
  ``NTSYNC_IOC_WAIT_ALL``; those non-consuming waits are signaled only when a
  queued packet has not been granted to a blocking remover.

  A signal handler installed without ``SA_RESTART`` may interrupt a blocked
  removal with ``EINTR`` and ``written`` set to zero. With ``SA_RESTART``, the
  removal restarts transparently against the same absolute timeout. Callers
  must handle ``EINTR`` when using non-restarting signal handlers.

  Packet selection and reservation are serialized, but userspace copies do
  not hold a port lock. Other posts, removals, and waits may proceed while a
  result is copied. Reserved packets remain unavailable to other removers
  until the copy succeeds or they are returned; concurrent removals may
  complete in a different order.

  If either the packet array or ``written`` cannot be copied to userspace,
  that removal's packets are restored in posting order unless the port is
  concurrently shut down. A granted packet is merged with any older returned
  packets before the batch is selected.

``NTSYNC_IOC_IOCP_READ``
  Returns the configured concurrency value and current queue depth.

``NTSYNC_IOC_IOCP_ABANDON``
  Advances the removal generation when the expected nonzero generation
  matches the current one. Blocked removers from the old generation wake with
  ``ECANCELED``, including removers that race with the operation. Queued
  packets and generic ntsync waiters are left intact so an object kept alive
  without an NT handle can be reopened and used again. The caller tracks the
  generation by incrementing it after each successful operation, skipping
  zero.

``NTSYNC_IOC_IOCP_SHUTDOWN``
  Permanently closes the kernel queue. This operation is idempotent and is
  reserved for terminal teardown or error recovery. Blocked batched removals
  wake with ``ECANCELED``, later removals fail with ``ECANCELED``, and posts
  fail with ``ESHUTDOWN``. Generic ntsync waits treat a shut-down port as
  permanently signaled. Pending packets are discarded and the reported queue
  depth becomes zero.

Remaining work
--------------

The concurrency value is not yet enforced. Wine integration must route every
producer for an accelerated port through the same kernel queue. Splitting one
port between kernel and wineserver queues would make FIFO ordering undefined.
